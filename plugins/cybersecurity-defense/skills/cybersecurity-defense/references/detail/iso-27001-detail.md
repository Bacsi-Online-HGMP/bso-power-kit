# ISO/IEC 27001:2022 — Annex A controls & standards reference

Read when you need the full control list or the ISO family map for the
`iso-27001-isms` playbook. A blank audit checklist is in
`assets/iso-27001-audit-checklist.md`.

## 27001:2022 vs 2013
Annex A restructured from 14 domains to **4 themes**, **93 controls** (was 114),
**11 new**. Clause 6.3 (planning changes) added. Title now includes "Cybersecurity
and Privacy Protection."

## ISO 27000 family (supporting)
27002 (control implementation guidance) · 27005 (risk management) · 27017 (cloud
controls) · 27018 (PII in public cloud) · 27701 (privacy/PIMS, GDPR support) ·
27006/27007 (certification & audit).

## Annex A — A.5 Organizational (37)
Policies (5.1); roles & responsibilities (5.2); segregation of duties (5.3);
management responsibilities (5.4); contact with authorities / interest groups
(5.5–5.6); **threat intelligence (5.7, NEW)**; security in project management (5.8);
asset inventory / acceptable use / return (5.9–5.11); classification & labelling
(5.12–5.13); information transfer (5.14); access control / identity / auth info /
access rights (5.15–5.18); supplier & ICT supply-chain security (5.19–5.22);
**cloud-services security (5.23, NEW)**; incident management planning, assessment,
response, learning, evidence (5.24–5.28); continuity & **ICT readiness (5.29–5.30,
5.30 NEW)**; legal/IP/records/PII (5.31–5.34); independent review & compliance
(5.35–5.36); documented operating procedures (5.37).

## A.6 People (8)
Screening (6.1); employment terms (6.2); awareness/training (6.3); disciplinary
process (6.4); post-termination responsibilities (6.5); NDAs (6.6); remote working
(6.7); security event reporting (6.8).

## A.7 Physical (14)
Perimeters & entry (7.1–7.2); securing offices/rooms (7.3); **physical security
monitoring (7.4, NEW)**; environmental threats (7.5); secure areas (7.6); clear
desk/screen (7.7); equipment siting / off-prem / media (7.8–7.10); utilities &
cabling (7.11–7.12); maintenance & secure disposal (7.13–7.14).

## A.8 Technological (34)
Endpoint devices (8.1); privileged access & access restriction (8.2–8.3); source-code
access (8.4); secure authentication (8.5); capacity (8.6); malware protection (8.7);
technical vulnerability management (8.8); **configuration management (8.9, NEW)**;
**information deletion / data masking / DLP (8.10–8.12, NEW)**; backup & redundancy
(8.13–8.14); logging (8.15); **monitoring (8.16, NEW)**; clock sync (8.17); privileged
utilities / software install (8.18–8.19); network security, services, segregation
(8.20–8.22); **web filtering (8.23, NEW)**; cryptography (8.24); secure SDLC,
app-security, architecture (8.25–8.27); **secure coding (8.28, NEW)**; security
testing, outsourced dev, env separation (8.29–8.31); change management (8.32);
test information (8.33); protection during audit testing (8.34).

## Certification path
Stage 1 (document review) → Stage 2 (on-site implementation audit) → annual
surveillance (Yr 1–2) → recertification (Yr 3). Accreditation bodies: UKAS, ANAB,
DAkkS, JAS-ANZ, COFRAC.
